# Internationalization direction

Status: supported-locale primitives and per-business enabled/default locale state are implemented;
content localization, locale routing, and translation delivery remain deferred.

## Initial market

| Setting           | Value            |
| ----------------- | ---------------- |
| Market            | Israel           |
| Currency          | ILS (`₪`)        |
| Platform timezone | `Asia/Jerusalem` |

The supported languages are:

| Locale | Language | Direction | Typeface |
| ------ | -------- | --------- | -------- |
| `ar`   | Arabic   | RTL       | Cairo    |
| `he`   | Hebrew   | RTL       | Heebo    |
| `en`   | English  | LTR       | Ubuntu   |

`@darb/i18n` owns the shared locale identifiers and direction primitives. It does not contain
business-specific translations.

## Business language state

`core.businesses.default_locale` remains the single canonical default. `core.business_locales`
stores the enabled set for that business. The database enforces these invariants:

- only `ar`, `he`, and `en` are accepted;
- a business has one to three enabled locales;
- its default is always enabled;
- changing the default and enabled set is atomic through `core.update_business_locales`;
- new and migrated businesses receive an enabled row for their existing default.

The `/b/[businessSlug]/languages` page exposes this state to authorized members and requires
`business.manage` for changes. Locale rows describe availability only; they are not a generic
translation store.

## Direction and layout

Applications must set valid `lang` and `dir` attributes at the document boundary. Components must
use logical CSS properties where possible and explicitly isolate mixed-direction text such as
addresses, telephone numbers, codes, and brand names. RTL support affects navigation order,
alignment, directional icons, transitions, and spatial assumptions—not just text alignment.

Keyboard behavior, screen-reader announcements, truncation, tables, forms, and responsive layouts
must be tested in both directions. Mirroring an icon is a semantic decision; icons such as media
controls or brand marks should not be mirrored automatically.

## Formatting and time

Dates, times, numbers, plural forms, and currency must use locale-aware platform APIs. Store and
transport unambiguous timestamps; render them with the correct business or platform timezone. Do
not concatenate translated fragments or assume that ILS formatting is identical across languages.

## Deferred decisions

- runtime fallback and negotiation policy beyond the canonical business default;
- locale negotiation and persistence;
- URL locale strategy;
- translation catalogue tooling and ownership;
- server/client message-loading boundaries;
- engine-owned multilingual content models. Prefer domain-specific localized tables or fields when
  a real engine defines its query and validation needs; do not introduce a generic EAV translation
  table prematurely.

These decisions require product and SEO requirements. The current application shell is English for
infrastructure validation and does not establish the platform's permanent default locale.
